→ 버튼의 상태(State)에 따라 어떤 일이 진행되고 있는지 알려주는 기능 정리하기

## 1. Button/Badge 상태 만들기
- 상태가 필요한 이유
    - State: 같은 요소가 상황에 따라 바뀌는 모습(화면만 보고 사용자의 다음 액션을 알게 함.)
        <details>
        <summary>멘탈모델: 어떻게 생각하는가? - 세상을 바라보고, 이해하고, 판단하는 사고의 도구</summary>
        문제 해결: 복잡한 문제를 구조적으로 이해할 수 있음<br>
        의사결정: 감정이나 직관에만 의존하지 않고 합리적으로 판단 가능<br>
        학습 능력: 새로운 지식을 기존 지식과 연결해 빠르게 이해<br>
        예측 능력: 상황의 변화와 결과를 미리 예상
        </details>

    - 디지털에서도 사용자가 인터렉션 할 수 있는 힌트를 제공!

- 상태 5종
    - Default - 기본
    - Hover - 마우스를 올림
    - Pressed - 누르는 중
    - Focus - 키보드로 선택됨
    - Disabled - 사용불가<br>
    → 모바일 앱에는 Hover가 없어 손가락이 닿은 순간은 Pressed로 보여줌.

- 버튼 위계와 크기: 버튼의 중요도 순서
    - Soled(=Filled, Contained), 아웃라인, text(=ghost)
    - Primary, Secondary, Tertiary(세번째 중요도), Assistive(보조)
    - Large, Medium, Small

- 상태별 색 규칙
    - 새로운 색을 만들지 않고 기존 컬러에서 진하거나, 회색으로 낮추는 방법을 사용함.
    - opacity를 사용하는 경우도 있으나, 배경색이 비쳐보일 수 있음<br>
    → 반대로, 이미지위의 회색조 요소가 부자연스럽게 비치는 경우 투명도를 적용.

- 버튼 크기: 자주 쓰는 높이 3가지를 정해두고 높이는 고정, 너비는 글자에 맞게 늘어남. => 세로 크기 : 패딩+폰트 크기로 고정된 값을 사용

- Badge 3종
    - 숫자, 라벨, 점으로 상태나 새 소식을 한눈에 알려줌.
        - 숫자가 1처럼 줄어드는 경우 min width 등으로 기본 모양이 일정하게 유지되게 설정.
        - 컬러: 빨간색은 꼭 강조해야하는 내용에만 적용
    - 긴 라벨: 너비를 Hug conent로 두고, 짧은 글자는 min width로 최소 너비를 지키기.<br>
    → 터치 반경을 고려해 사용성을 높이는 디테일.

## 2. Input Field 상태 설계
- 입력 필드의 구조
    - 여러 정보를 담은 부품들을 세로 auto layout으로 쌓은 묶음

    | 이름 | 역할 |
    |---|---|
    | Label | 무엇을 넣는 칸인지 |
    | Field | 누르는 칸(테두리, 배경) |
    | Icon | 칸의 종류를 이미지로 빠르게 알려줌 |
    | Placeholder | 입력칸이 비었을 때 보이는 text이자 입력 예시 |
    | Helper text | 입력 전 칸 아래의 도움말 |
    | Error message | 틀렸을 때 바뀌는 문구 |
    
    <br>
    → 에러 메세지는 원인+다음 행동에 대한 설명으로 정확히 표기하는 것이 중요.<br>
    - 필수: label 옆 빨간 별표 $\color{#E5484D}{\text{*}}$ <br>
    - 선택: label 옆 회색 글씨 $\color{#999999}{\text{(선택)}}$ <br>
    
    <br> 

- Input Field 5가지 상태 - 사용자가 어떤 입력 상태인지 글자와 테두리 변화로 알려주는 것.
    - empty(blurred): 비어있음
    - focus: 입력 중(커서가 위치)
    - filled: 입력 완료
    - error: 형식 틀림
    - disabled: 입력 불가<br>
    → 검색 Input에는 별도의 label을 달지 않는데, 이유는 돋보기 아이콘과 placeholder(검색어 예시)가 함께 보여지기 때문<br>
    → filled에서 입력된 값은 'value'로 지칭.

- 에러 문구
    - 원인 + 필요한 행동: 실패 안내에는 원인과 다음 행동을 함께 다룰 것.
    - 알려주는 시점: 입력칸을 벗어났을 때 알려줌.<br>
    → 입력중에 실시간으로 알려주면 혼나는 느낌을 받아 지양하기도 함.
