## 1. Figma skill을 익혀야하는 이유
- Figma와 AI 에이전트<br>
    : ai가 화면을 만들어도, 아직 결과를 고치고 협업하는 기준은 Figma의 구조를 따르는 경우가 많음<br>
    (실무 표준도구이며 프로토타입의 기본 틀이되는 도구. 또한, ai 에이전트가 만든 결과물의 구조를 알아야 수정할 수 있음)

- MCP(Model Context Protocol)
    - 레이어 이름과 구조가 그대로 사용되므로 설계를 잘 해야함
    - MCP에 연결 가능한 앱은 다양하며 Figma도 그 중 한 종류
    - AI 도구에 권한을 부여해 직접 작업이 가능하게 함

- 레이어 이름 규칙: 디자인 시스템<br>
    1. 영역은 역할로: 어떤 기능을 담은 영역인지 이해 가능하게 짓기<br>
    ex.header, search-bar, tab-bar
    2. 계층구조를 나타낼 땐 슬래시로<br>
    ex. Button / Primary, Button / Secondary -> Button의 하위 요소에 Primary와 Secondary가 존재.
    3. 생성 직후 새겨진 기본 이름 남기지 않기<br>
    ex.Frame 12, Rectangle 3<br>
    => ***정리된 이름은 개발자, AI, 미래의 나까지 읽는 중요한 정보임!!***


## 2. 도형/펜툴/Boolean으로 아이콘 만들기
- 아이콘의 3가지 규칙
    | 크기: 24x24 | 선 두께 | 끝 모양 |
    |---|---|---|
    | 8의 배수*<br>keyline**을 사용해 제작 | 같은 두께의 선 사용<br>주로 center 사용<br>join: 관절, 꺾이는 부분 | 아이콘의 모서리 통일하기 |
    - ***8의 배수*: 일관된 레이아웃을 구축하는 디자인 규칙.***<br>
    -> 다양한 화면 크기에 대한 대응과 개발 협업의 효율성을 위해 지켜야 함.<br>
    -> 일정한 단위 체계를 사용해 간격과 크기를 체계적으로 관리함.<br>
    -> 2로 나누거나 곱하는 등 상황에서 소수점이 발생할 가능성을 줄임.
    - keyline**: 착시를 보정하고 아이콘을 일정하게 만들기 위해 만든 Guide line


- 도형: 사각형, 원, 선, 화살표, 다각형<br>
    -> 버튼의 배경은 프레임이나 오토 레이아웃을 주로 사용.<br>
    -> Outline Stroke: 선을 도형으로 변환. 수정이 필요한 동안은 Stroke 상태를 유지하고 작업이 끝났을 때 변환한다.(cmd+e) 

- 펜툴: 점을 찍어 선을 그리는 도구. 클릭+드래그하면 곡선<br>
    -> enter: 편집모드 전환. 점, 핸들 조정이 가능하다.

- Boolean 4가지 - 빼고싶은 영역을 레이어 상단에 위치함<br>
    > 레이어 2개를 선택해야 사용 가능
    - Union: 합치기
    - Subtract : 위 레이어 영역만큼 빼기
    - Intersect: 겹친 곳만 남기기
    - Exclude: 겹친 곳만 비우기

- 크기 조절과 스케일(k)의 차이<br>
    : 크기는 선에 영향을 주지 않지만 스케일은 커지는 만큼 선이 굵어짐(배율)

## 3. 텍스트/컬러/이펙트 스타일 기초
1. 텍스트 속성
    - 글꼴, 크기, 행간, 자간
    - 행간 단위: 비율과 픽셀의 차이<br>
        -> 비율(%): 글자 크기를 바꿔도 비율이 유지됨. 글자 크기에 맞춰 늘어나는 가변적 단위<br>
        -> 픽셀(px): 글자 크기의 변화에 상관없이 고정적으로 유지되는 단위.

2. 색과 스타일 등록
    - Fill, Stroke(Border/Line), Effect
    - 스타일 등록(Style과 Local variable)
        - 자주쓰는 글자, 색, 그림자 값에 이름을 붙여 저장한다.
        - Local variable은 디자인 시스템 토큰을 잘 활용하기위해 만들어둔 것.
        - Style은 MVP만 빠르게 디자인 할 때 주로 사용함.
    - 스타일 등록을 하지 않은 채 디자인의 변화나 상징 컬러가 변경되면 일일히 바꿔줘야하는 수고가 발생 XXX

## 4. Frame/Constraints/Layout Grid로 화면 배치
1. Frame/Group/Section 의 차이
    - 모두 레이어를 묶는 방법의 하나.
    - 크기를 바꿀 때 영역 안 요소가 어떻게 바뀌는지가 가장 큰 차이점.
        - Group: 요소간 정렬이나 간격 조정이 불가. <br>
        (따라서 임시로 함께 옮겨야하는 경우 등에만 사용)
        - Frame: 주로 화면 단위로 사용
        - Section: 화면 여러장을 구분지어 정리할 때 사용.<br>
        (제목을 넣는 칸이 생김)

2. Constraints - 스크린 사이즈 대응
    - 프레임 크기가 바뀔 때 요소가 화면의 어디에 고정되어야 하는지 정하는 규칙.<br>
    : Top bar, Bottom bar 등 화면의 크기가 변해도 지정된 위치에 있어야 하는 요소들의 값을 조정함.
    - 오토 레이아웃을 프레임에 적용하면 Constraints가 해제되고 적용할 수 없음.<br>
    → 따라서 부모가 프레임일 경우에만 적용 가능함.

3. Layout Grid - 요소를 같은 폭, 간격에 맞추는 보이지 않는 안내선.
    - 모바일 4단(6단) 그리드<br>
    - Margin: 화면 가장자리 여백
    - Gutter: 칸과 칸 사이의 간격
