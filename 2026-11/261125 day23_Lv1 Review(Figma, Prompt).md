## 1. PD 직무의 이해
- 화면이 아니라 문제와 결과까지 책임지는 디자이너
    - 화면 표현(시각적 완성도) → 사용 흐름/사용성 → 문제와 결과로 역할이 넓어짐.<br>
    GUI → UX디자이너 → ***Product Designer: 문제와 결과, 사용자/비즈니스 지표***
- 채용공고에서 빠지지 않는 4가지 역량
    - 문제 정의, 설계, 검증, 협업
- AI로 인해 바뀐 것
    - 디자인 → 문서 → 개발 단계의 리소스가 크게 감축됨.

## 2. AI Literacy(Prompt)
- 그럴듯한 다음 말을 만드는 도구(LLM)
    - 토큰을 가지고 확률적으로 문장을 만들어냄.
    - **6가지 구성요소**로 프롬프트를 작성: ***역할, 맥락, 과업, 제약, 형식, 예시***
    - AI 한계: 출처, 숫자, 최신성 확인하기<br>
        → 정보를 하나씩 쪼개고 1차 출처를 찾아 판정/확인일 남기기
        
    - 책임있는 활용: 개인정보, 저작권, 사용 사실 밝히기<br>
        → AI 사용 사실을 밝히는 게, 표절 의혹을 피하는 가장 수월한 방법.
        
- 동료 테스트: 상황을 모르는 동료가 읽어도 이해 가능한지 확인하는 방법<br>
    → 동료가 헷갈리면 AI도 헷갈리는 지점이 존재.
    
- 프롬프트 v1 → v3 개선해가며 과정 기록하기
    - 해결하려는 상황(문제), 프롬프트 내용, 사용한 도구, 버전, 날짜

## 3. Auto Layout

> Figma → 구조를 만드는 도구

- 레이어 이름: 정리된 이름은 개발자, AI 도구, 동료가 함께 읽는 중요한 정보
- Auto Layout: 일정한 간격을 유지해야하는 요소끼리 자동 정렬/맞춤
- UI 상태: Button, Input 등의 요소에 사용자가 인식가능한 상태를 적용
- 컴포넌트: Main으로 한 번 만들고 Variant로 상태를 체계로 관리
- Prototype, Interaction: Trigger와 Action으로 화면의 흐름을 보여주는 시안.
- Fill, Hug, Fixed: 레이어의 크기를 부모요소 혹은 자식요소의 크기에 따라 영역을 정함.
- 방향, 간격, 패딩, 정렬: 오른쪽 패널에서 지정
- 중첩 구조: 가장 작고 가까운 요소끼리 묶어 점차 안에서 → 밖으로 영역이 넓어짐.

## 4. Variant, Property
- Variant vs Property 차이점
    - Variant: 모양이 바뀌는 컴포넌트에 사용. 상태(state), 크기(size), 종류(type) 등
    - Property: 내용이 바뀌는 컴포넌트에 사용. Text, 배지 On/Off, 하트 아이콘 ↔ 검색 아이콘<br>
    → 레이어 네이밍할 때 계층으로 ‘ / ‘ 구분지어 작성하면 variant set 만들 때 속성 제목만 입력하면 됨.
    
- Property 3종류: 생성 후 레이어와 연결하지 않으면 경고 아이콘이 뜸
    - Text
    - Instance swap
    - Boolean → 한 요소를 보이지 않게 했을 때 레이아웃이 깨지면, spacer를 활용.<br>

> 소문자로 이름 짓기: React와 네이밍 규칙을 일치시킴.

## 5. UI Component 이름과 사용법
- 대체로 역할은 구분돼있지만, 서비스 상황과 목적에 따라서 원래 용도와 다르게 변형하기도 함.<br>
ex. 바텀시트는 강제되는 요소는 아니지만 모달처럼 사용자에게 선택을 필수적으로 받는 상황에서도 사용.

    > ✅ 따라서 이름과 용도가 정해진 UI를 정답처럼 사용하는게 아니라, 각 UI들이 왜 이런 형태를 가지게 됐는지 의미와 목적을 이해하는 것이 중요하다.<br> 
    결국 내가 구성해야 할 화면 맥락(user-flow)에 따라 UI를 적재적소에 활용하고 어떻게 변형할지 판단할 줄 아는 것이 핵심.

[복습하며 느낀 점]
- tab과 segment 용도의 차이는 알지만 UI의 차이는 아직 헷갈린다. 어떻게 구분해서 사용해야 할까?(내용으로 구분짓는게 중요한지, UI의 형태도 중요한지?)
    > 둘을 가르는 1차 기준: 내용이 아닌 ***"동작의 의미"***
    - 핵심 판단 기준: 선택하면 무엇이 바뀌지?
    1. Tab > 선택하면 콘텐츠 영역 자체가 바뀐다.<br>
    서로 다른 내용을 가진 '방'을 오가는 느낌. 탭마다 보여주는 콘텐츠와 구성이 바뀐다.
    2. Segment > 같은 콘텐츠를 보는 방식이 바뀐다.<br>
    정렬, 기간, 보기 형식같은 속성을 변경. ex. 일간|주간|월간, 지도|위성

    - 빠르게 판단하는 질문
        - 선택지를 바꾸면 완전히 다른 종류의 콘텐츠가 나오는가? > tab
        - 같은 데이터를 다르게 보여주는 것인가? > segment

    > ***사용자가 이동했다고 느끼면 tab, 보기 설정을 바꿨다고 느끼면 segment***
