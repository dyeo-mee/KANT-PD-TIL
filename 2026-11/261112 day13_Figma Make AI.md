## 1. Figma Make로 프롬프트 기반 프로토타입 만들기
- Figma Make: 프롬프트로 동작하는 프로토타입 웹/앱을 만드는 AI 도구.

- Design 프로토타입과 비교<br>

    | 항목 | 디자인 프로토타입 | Make AI 프로토타입 |
    |---|---|---|
    | 만드는 법 | 화면을 직접 그리고 연결 | 프롬프트로 요청하면 코드로 생성 |
    | 수정 | 레이어, 속성을 직접 수정 | 대화로 요청, Edit으로 부분 수정 |
    | 결과물 | 디자인 파일, 클릭 프로토타입 | 동작하는 웹/앱(코드), 공유링크 |
    | 용도 | 디자인 기준 정리, 개발팀 전달 | 아이디어 빠른 검증 |
    | 비용 | AI 크레딧 들지 않음 | 요청마다 AI 크레딧 소진 |


- 프롬프트 구조
    - Make 프롬프트 5칸<br>
    : 사람에게 부탁할 때 “그냥 만들어줘”라고 요청하면 막막하고, 답답하듯이<br>
    *AI에게 요청할 프롬프트 내용도 구체적이어야 함.*

        | 소제목 | 쓸 내용 | 빠지면 생기는 일 |
        |---|---|---|
        | 목표 | 만들 화면과 이유 | 엉뚱한 화면, 필요없는 요소 |
        | 맥락 | 서비스, 사용자, 이전 화면 | 아무 앱이나 반영한 그럴듯한 화면 |
        | 화면 요소 | 꼭 들어갈 정보, 버튼 | 중요한 정보가 빠짐 |
        | 제약 | 화면 크기, 색, 글꼴, 금지 사항 | 색 여러 개, 이모지 아이콘 |
        | 완성 기준 | 트리거, 상태 변화 | 버튼이 기능하지 않고 상태 없음 |

        → 예시는 화면을 직접 첨부하는게 절대적으로 좋음!! **첨부 메뉴의 + Add context**<br>
        *혹은, Figma Design 파일에서 직접 복사 붙여넣기*

- 대화형 수정
    - v0 → v3 수정: 한번에 하나씩 바꿔야 무엇이 효과였는지 보임.
        - 수정 프롬프트는 바뀐 것만 짧게 작성함.
        - 무엇을 어떻게 바꾸고 그대로 둘 것은 어떤 것인지 작성.
    - 디자인 맥락을 제공하기
        - 텍스트로 설명하는 말보다, 프레임 첨부가 훨씬 더 정확함.
        - 프레임 5장 첨부: 색, 간격, 글꼴 값을 읽어 씀. 같은 버튼/카드 모양으로 생성,<br>
        5장의 프레임이 가진 흐름을 참고해 결과물을 생성.

- Edit 수정
    - 원하는 지점을 콕 찝어서 어떻게 수정할지 요청 가능함.

>요청이 중복되면 어떤 요청으로 인해 바뀐지 알 수 없어 크레딧을 낭비하게 됨.<br>
요청 1개에는 바꿀 것을 하나만 지정해 줄 것!!

## 2. AI 생성 결과 검수와 보정 기준
- 생성 결과 검수의 5가지 축
    1. 일관성: 색, 글꼴, 간격 등 스타일이 팀/프로젝트의 기준에 맞는가?
    2. 상태: Pressed, Disabled가 적절한 요소에 적용됐는가?
    3. 구조: Auto layout 묶음, 레이어 이름, 상태바/탭바의 배치가 적절한가?
    4. 컴포넌트: 팀/프로젝트에서 사용하는 컴포넌트와 아이콘을 사용했는가?
    5. 내용: 지어낸 수치나 문구는 없는가? 글자 대비가 충분한가?

- 보정 순서<br>
    : 구조 → 컴포넌트 교체 → 상태 → 문구<br>
    - 구조가 먼저 잡혀야 교체, 상태 추가가 깨지지 않음

- 전/후 기록표<br>
    : 무엇을 왜 고쳤는지 남겨야 다음 프롬프트가 좋아짐.<br>
    - 사용한 프롬프트, 수정 지점, 이유를 한 줄씩 꼭 작성하기!
