## 1. AI 도구 선정 기준
> AI 도구를 고르는 기준<br>
디자인 워크 플로우마다 맞는 도구 찾기<br>
여러 도구를 이어서 쓰는 방법

- 더블 다이아몬드: 확산과 수렴을 두 번 반복해 문제를 해결하는 방법론.
    - 확산: 다양한 가능성을 탐색하고, 정보를 넓게 수집하는 과정
    - 수렴: 수집한 정보 중 핵심을 선택하고 범위를 좁히는 과정
    1. Discover(발견) - 문제 파악, 양질의 정보 수집, 관찰 ex. 사용자 조사/인터뷰
    2. Define(정의) - 핵심 문제 정의 및 프로젝트 방향성과 전략 수립 ex. 데이터 분석, 페르소나, 사용자 여정 지도
    3. Develop(개발) - 해결 방법 도출 ex. 브레인 스토밍, 와이어프레임, 프로토타이핑
    4. Deliver(전달) - 가장 적합한 해결책 채택 ex. 사용성 테스트, 검증, 피드백 수집 및 개선
    
    > AI 도구를 고르기 전, 현재 디자인 워크플로우 위치가 어딘지 파악하기 = 적합한 AI 찾기

### 모델은 왜 다르게 답할까

- 답이 만들어지는 재료
    1. 학습한 지식 - 어느 시점까지 무엇을 배웠나?
    2. 지금 넣은 자료 - 대화/파일 = 컨텍스트
    3. 생각하는 방식(추론) - 바로 답할까, 단계를 거칠까
    4. 검색 결과 - 웹에서 찾아 온 최신 정보<br>
    → 모델마다 회사가 추구하는 가치관이 다르기 때문에 같은 입력에도 답변이 달라짐.

    - 학습 시점(Knowledge Cutoff), 검색: 검색없이 물어보면 모르거나 지어낼 수 있음(할루시네이션)
    - 컨텍스트 창(Context Window): AI가 한번에 읽을 수 있는 양 → 많은 양은 잘라서 입력하기
    - 추론 모드(Reasoning): 답하기 전 단계를 거쳐 생각하는 모드(조건이 많거나 깊은 사고가 필요한 질문)<br>
        → ex.클로드 ‘노력’정도에 따라 답변 시간과 결과물 퀄리티 차이가 많이 남

### 선정 기준 6가지
1. 출력 품질: 결과물이 바로 쓸만한가?
2. 컨텍스트 길이: 한번에 읽고 기억하는 양 비교하기
3. 멀티모달: 글 외의 입력/출력 확인
4. 검색 연동: 최신 정보와 출처 
5. 비용: 무료 한도와 유료 가격 비교
6. 데이터 정책: 입력한 내용이 어디에 쓰이는지 (AI 도구 회사 정책 등)<br>
→ 입력한 데이터가 모델 학습에 쓰이는 상황 등 회사 내부 규정 준수하기.

    - 기준이 충돌하는 경우
    
        | 상황 | 부딪히는 기준 | **먼저 볼 것** |
        | --- | --- | --- |
        | 고객 문의 5,000건 분석 | 컨텍스트 길이 vs 데이터 정책 | **데이터 정책** |
        | 경쟁 앱의 이번 달 환불 규정 | 출력 품질 vs 검색 연동 | **검색 연동** |
        | 문구 100개를 매일 생성 | 출력 품질 vs 비용 | **비용** |
        | 화면 캡처로 문제 찾기 | 멀티모달 vs 비용 | **멀티모달** |
        - 도구 고르는 순서
            1. 할 일을 한 줄로 작성: 무엇을 만들지 한 문장으로 정리
            2. 핵심 기준 1~2개 정하기: 없으면 안되는 기준이나 제한
            3. 후보 2~3개 실행: 같은 과업과 같은 프롬프트로 비교
            4. 선택과 근거 기록: 이유와 함께 어떤 도구가 유용했는지 기록

## 2. 디자인 태스크 별 도구 매칭
- 디자인 태스크와 핵심 기준
    1. 리서치: 검색 연동 - 출처 링크가 열리고 맞는 내용인가?<br>
    → 규정 요약+출처 링크, 또한 내용이 맞는지 대조<br>
    → 리서치를 하는 목적과 기준이 뭔지 정해놓고 사용하는 것이 중요
    2. 카피라이팅: 출력 품질 - 원하는 톤, 글자 수, 맥락을 지켰는가?<br>
    → 같은 요청을 도구 2~3개에 넣고 조건을 지켰는지 비교하기
    (ex. 토스 보이스톤 문서 )
    3. 시안 생성: 멀티 모달 - 화면으로 결과를 확인하고 고칠 수 있는가?<br>
    → 프롬프트: 화면 설명(누가, 어떤 상황, 무엇을), 초안 만들고 고치기, 최종 검토(접근성, 디자인 시스템)
    4. 데이터 분석: 컨텍스트 길이/ 데이터 정책 - 파일에 빠진 내용은 없는지, 개인정보 유무 확인<br>
    → 숫자는 계산 방법도 함께 알려달라고 할 것 ⇒ 결과를 직접 확인하기 위함

    > **도구에 맞는 체크리스트와 검수 환경을 마련할 것**

- 각 도구에게 태스크를 넘겨주기(입력/출력)
    - 한 도구로 업무가 끝나지 않기 때문에 앞 단계 결과물을 다음 도구의 입력으로 넘겨줌.
    - 다음 도구로 넘어가기 전에 결과를 표, 문서로 정리하기(버전 업데이트, 한 요청에 한 요구사항 만)

        | Work Flow | 입력 | 출력 |
        |---|---|---|
        | 리서치 | 사용자 문제 작성 | 조사 자료 및 출처 |
        | 설계 | 조사 자료 및 출처 | 흐름도, 문구 원칙(톤, 단어 수) |
        | 프로토타이핑 | 흐름도, 문구 | 프로토타입 결과물, 링크 |
        | 검증 | 프로토타입 | 유저테스트 결과 정리 |

## 3. 도구 조합 워크플로우
> 단계 사이에 넘길 입력/출력을 정할 수 있음<br>
사람이 검토해야 하는 지점을 표시할 수 있다<br>
도구 조합 워크플로우 다이어그램 제작 가능

- 리서치 → 설계 → 프로토타이핑 → 검증
    1. 리서치: 문제와 사례 모으기 ex. 검색형 AI, LLM
    2. 설계: 흐름, 구조, 문구 정하기 ex. LLM, FigJam
    3. 프로토타이핑: 화면으로 제작 ex. Figma Make, Google Stitch
    4. 검증: 사용자, 팀과 확인하기 ex. LLM

- **사람이 검토하는 지점**(Human-in-the-loop): *AI 결과가 다음 단계로 넘어가기 전, 미리 검수 영역을 정함.*
    - 사실 확인 - 출처, 숫자가 맞는지 확인
    - 맥락 확인 - 우리 서비스, 사용자에 맞는지 검토
    - 결정 - 무엇을 채택하고 무엇을 버릴지 결정

    > ✅ AI는 후보를 만들고, 채택은 사람이 근거로 결정해야한다.
