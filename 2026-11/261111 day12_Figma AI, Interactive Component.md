## 1. Interactive Component로 상태 전환
- 상태 전환의 두 가지 방식
    - 화면 복제 vs *Interactive Component*<br>
        : 상태가 바뀌는 UI는 인터랙티브 컴포넌트로 간단하게 전환이 가능함.
        - 요소가 바뀔 때마다 화면을 복제하면 상태 조합만큼 수가 늘어남.
        - 인터랙티브 컴포넌트를 사용하면 화면 1장에 내용이 바뀔 variant 요소끼리 연결하고, 다른 화면에 갖다놔도 동일한 인터랙션이 적용된다.
        ***→ 따라서 화면을 오가는 흐름은 화면 연결로, 일부만 바뀌는 상태는 Interactive Component로 제작!***

- Variant 연결
    - On <=> Off : Change to<br>
    → 같은 컴포넌트 세트 안에서 Variant를 바꾸는 동작
    - 연결 순서<br>
    : 메인 컴포넌트들을 세트로 만들어주고 각 variant에 state: value 지정. 프로토타입 들어가 인터렉션 추가 smart animate 지정.
    - 동작 조건
        - *같은 세트에 존재하는 variant에만 지정 가능*
        - **화면에는 인스턴스만 들어가야함**
        - 움직일 레이어는 이름과 구조(순서)가 같아야함
        - prototype 연결을 끊어도 reset을 누르면 부모 컴포넌트의 설정을 다시 따라감
    - Trigger 별 전환
        - On tap: 되돌리는 상태도 만들기
        - While hovering(모바일 앱 X)
        - While pressing<br>
        → While 은 되돌아오는 설정을 따로 주지 않아도 됨.

- 사용 예시: 한 화면 안에서 일부만 바뀌는 UI → 모두 variant 2개 이상<br>
    ex.토글/체크박스, 찜 버튼, 탭 전환, 수량 스테퍼

- 프로토타입에 배치<br>
: 화면 흐름은 Navigate to로 이어주고, 화면 안 상태 변화는 Interactive Component 인스턴스가 맡는다<br>
*→ after delay: 무조건 화면 전환! 인터랙티브 컴포넌트가 아님*
    
    - Navigate to & Change to

    | 구분 | Navigate to | Change to |
    |---|---|---|
    | 바뀌는 범위 | 화면 전체| 인스턴스 하나 |
    | 연결 대상| 다른 화면 프레임 | 같은 세트의 다른 Variant |
    | 연결하는 곳 | 화면 안의 버튼/카드 | 컴포넌트 세트 안 Variant |
    | 되돌아가기 | Back 또는 반대 연결 | 반대 방향 Change to 지정 |
    | 사용 예시 | "결제하기" 버튼 -> "결제완료" 페이지 | "날짜 칩" 선택 -> 선택한 날짜 칩의 "상태" 변경 |


## 2. Figma AI 
> 기능별 검수 포인트와 크레딧 소모를 알고, 쓸지 말지 판단하기
- 반복 작업 단축형 vs 생성형
    - 반복 작업 단축형: 규칙에 맞는지 검수해야함. 이미 만든 것을 빠르게 정리하는 기능
        - Rename layers: 기본 이름 만 골라 내용, 위치를 보고 이름을 붙여줌.<br>
        → 붙여준 이름을 바로 사용하지 않고, 팀 규칙에 맞춰 검수해줘야함.
        - Suggest auto layout: 흩어진 요소를 보고 어떤 것끼리 묶을지 판단해 중첩 auto layout을 만들어줌.<br>
        → 대략적인 위치는 미리 지정해줘야함.
        - 이미지/글 도구: 사진과 문구를 다듬는 기능<br>
        → 배경 제거(머리카락/손끝 검수), 해상도 높이기, 번역/단어 줄이기, 예시 내용 채우기(가짜 데이터)<br>
        ***→ more: vectorize 아이콘 뽑아내기 적절한 기능***

    - 생성형: 사실, 의도와 다른게 없는지 검수해야함. 없던 것을 새로 만드는 기능
        - 생성형 기능 종류

        | 기능 | 만드는 것 | 어디서 | 검수할 것 |
        |---|---|---|---|
        | Ai 에이전트 | 화면 시안 | Action 메뉴/cmd+k | 컴포넌트, 색 |
        | Add interactions | 화면 연결 | Prototype 탭 | Dead end 구간, 뒤로 가기 기능 |
        | Make image | 이미지 | Action 메뉴 | 편향, 실존처럼 보이는 것 |
        | Rewrite this | 문구 | Action 메뉴 | 사실, 서비스 정책과 다른 것|

        - AI 기능 쓰는 순서
            1. 범위 고르기: 카드 1개, 영역 1개 등 작게(크레딧 등을 고려해서 계획하기)
            2. AI 실행: 작업에 쓰기 적절한 기능 고르기.
            3. 검수: 팀/프로젝트 기준에 맞춰 수정해야할 내용 정리
            4. 고치기: 레이어 이름, 구조, 이미지 왜곡, 맥락에 맞는 문장 등을 수정.
            5. 기록: AI에게 맡긴 일과 유용했던 점, 그럼에도 내가 판단해야 할 지점 회고하기.
        
        - Action 메뉴 ***cmd+k***<br>
        → 같은 메뉴에서 플러그인도 사용 가능(컬러 팔레트 등 다양한 라이브러리)
        - AI 크레딧 - 에듀플랜은 매월 3,000 크레딧 사용가능.
