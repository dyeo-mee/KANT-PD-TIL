> ✅ UX 원칙/법칙을 개선하기 위한 UI 색채와 정보위계 알아보기<br>
UI에서 색이 주는 신호(의미)를 설명할 수 있다.<br>
원시값 → 아토믹 → 시맨틱 토큰 구조를 이해하고 Figma 변수를 설정할 수 있다.<br>
라이트 & 다크모드 차이와 모드 별 컬러 계층을 구분할 수 있다.

## 1. 색채 이론과 UI 컬러
[ 브랜드 컬러는 어디에 얼만큼 써야할까? ]

#### 색의 3속성
- 색상, 채도, 명도 3가지 값으로 설명함. (Figma: HSB)
    - 색상: 색의 종류 → 브랜드를 대표하는 색
    - 채도: 색이 얼마나 선명한지 → 채도가 높을수록 시선 집중(화면에 너무 많으면 안 됨.)
    - 명도: 색이 얼마나 밝은지 → 글자와 배경의 대비를 정해줌

- 명도와 대비: 대비가 낮으면 글자가 안 읽히고 중요한 버튼도 묻힘.<br>
→ 웹 접근성에서 대비율을 정해둠(대비율이 낮을수록 중요도가 떨어짐.)<br>
1.67 : 1 (거의 안 보임) <-> 5.52 : 1 (가장 선명하고 눈에 띔)

#### 역할별 컬러

- 컬러 역할: Primary, Secondary 처럼 역할로 정해두면 균형감 있는 화면을 만들 수 있음.<br>
→ 추후 브랜드 컬러가 바뀌더라도 열할 색만 변경하면 일일히 수정하지 않아도 됨. = 작업 효율성

- 컬러별 의미 - 문화별로 다를 수 있음.

    | 색상 | 의미 | 색상 | 의미 |
    |---|---|---|---|
    | 빨강 | 긴급, 오류, 할인 | 노랑 | 주목, 주의, 공지 <br> 단독은 가시성이 떨어지므로 어두운 색과 함께 사용 |
    | 파랑 | 신뢰, 안정, 확인 | 보라 | 특별함, 프리미엄 |
    | 초록 | 성공, 완료, 건강 | 검정 | 집중, 고급 |

- 상태 컬러(Semantic Color): 성공, 경고, 오류처럼 상태를 알리는 색

- 컬러 조합: 색상환에서 마주보는 컬러 → 보색(강조), 이웃한 색 → 유사색(안정, 편안함)

- 60%(기본색) : 30%(보조색) : 10%(강조색) 비율 <br>
    화면에서 색상 의미가 차지하는 적절한 비율

#### 디자인 토큰

- Color Scale: 색 하나를 밝기 단계(50~900)로 나눠두고, 알맞은 단계를 골라 씀.
    - Figma Action 메뉴의 Color Generator: 컬러 팔레트를 만들고 토큰으로 지정 가능.

- 컬러 토큰 구조: 원색→ 아토믹 → 시맨틱 순서로 이름을 쌓아 씀.
    1. 원시값: 컬러 코드 ex.#0057FF
    2. 아토믹 토큰: 컬러 코드에 이름을 붙임. ex.blue/500
    3. 시맨틱 토큰: 아토믹 컬러에 역할을 추가한 것. ex.background/brand
    4. 컴포넌트 토큰: 특정 부품 전용 색상(선택적, 대규모 프로젝트에서 사용)

- 디자인 토큰 파일<br> 
: 개발자도 읽을 수 있게 정리한 파일(주로 JSON). Figma 변수 → 토큰 파일 → 코드 순서로 넘어감.

- 시맨틱 이름 짓기: 요소/의도/강조(상태) - 이름만 봐도 쓰임을 알 수 있어야 함.<br>
ex. fg(요소)/ neutral(의도) / subtle(강조)
    - 요소: 스타일이 적용될 대상 (background, border, surface)
    - 의도: 토큰이 가진 의미 (neutral, brand, nagative)
    - 강조: 눈에 띄는 정도 (default, strong)
    - 상태: 요소가 가진 상태 (hover, pressed, focus)

- 라이트/다크 모드: 컬렉션 → 모드 → 변수로 정리함.
    - 같은 시맨틱 이름이 모드마다 다른 아토믹 색을 가리킴.
    - 라이트 ↔ 다크모드의 색은 한쪽의 컬러를 뒤집는게 아닌, 각각의 모드에 맞는 색을 새롭게 지정해줘야 함.
    - 라이트는 그림자 크기로, 다크 모드는 그림자를 볼 수 없기 때문에 면(Surface)의 밝기로 깊이를 표현함.

## 2. 타이포그래피 계층
> 타입 스케일을 정하고 Figma 텍스트 스타일로 정리하기.

- 글자의 계층: 글자의 크기와 굵기를 다르게 줘 중요한 정보를 인지하기 쉽게 함.
    - 역할별 단계로 나눠 크기, 굵기, 행간을 하나로 정해둠.<br>
    → Body: 본문, Caption: 부가 설명<br>
    → Display: 주로 웹화면에서 가장 강조되는 내용을 쓸 때.

- 타입 스케일: 글자 크기를 정해둔 단계. → 주로 6~7단계로 정해둠.
    - 모바일에서는 12이하 폰트는 사용하지 않는다. (접근성 문제)
    - 폰트 크기가 12~13일 경우 굵기는 Medium 이상으로 적용한다.<br>
    → 4배수, 8배수 규칙은 패딩, 간격 등에 사용하기 때문에 폰트와 무관함.

- 행간: 줄과 줄 사이 높이. 한글 본문은 150% 안팎이 읽기 편하다.
    - Display, Heading 등 제목은 120~130%로 줄여야 읽기 좋음.

- 자간: 글자와 글자 사이 간격. 보통 기본 자간(0)으로 쓰거나 아주 미세하게 조정. -0.01em ~ -0.02em(1~2%)

- 한글 서체 고르기: 잘 읽히는지, 굵기가 충분한지, 써도 되는지를 먼저 봄.
    - 가독성: 작은 크기에서도 잘 읽히는 고딕 계열을 주로 사용.
    - 굵기 단계: Regular, Medium, Bold 3개 이상.
    - 라이선스: 상업적 사용 가능한지 확인. → Pretendard, Noto Sans KR (가장 무난하게 많이 쓰는 폰트)

- 텍스트 스타일 지정: 타이포그래피 계층을 스타일로 등록하면 이름으로 씀. → 개발자도 같은 이름으로 받게 됨.

## 3. 아이콘 시스템
> 시각적 인식과 해석이 글보다 훨씬 빠르기 때문에 의미가 애매하면 더 큰 불편을 야기할 수 있음.

- 아이콘 스타일: 라인 or 면
    - 라인은 가볍고 깔끔함. 기본 상태에 많이 사용.
    - 면 아이콘은 눈에 잘 띄며, 상태 변화에 쓰기도 함.
    - 아이콘 형태(크기, 선 두께, 스타일)가 섞여있으면 상태가 불분명해지고 의미가 흐려질 수 있음.

- 크기와 터치 영역: 기본은 24. 작게는 16 or 20. 크게는 32
    - 아이콘이 24px여도 누르는 영역은 패딩이나 width/height Fill 옵션으로 손가락 크기만큼 넒게.<br>
    (터치 영역 권장: iOS - 44x44px, Android - 48x48dp)

- 라벨과 라이선스 - 뜻이 명확하지 않은 아이콘은 라벨과 함께 씀.<br>
    → 새로운 서비스에서 각 아이콘이 어떤 행동을 의미하는지 사용자가 파악하지 못 했을 때.<br>
    → 사용자 연령대, 문화권 혹은 운영체제마다 아이콘 인식의 차이가 존재함.

    - 라이선스 확인: 무료 아이콘도 사용 조건을 확인하기. (출처 표기, 상업적 이용 여부 등)<br>
    → Figma Action 탭 Plugin : Icon (React 아이콘 사용하면 개발자들도 바로 사용가능.)

- 정보 위계 설계
> 화면에서 가장 먼저 봐야 할 정보를 정할 수 있다.<br>
크기, 대비, 여백, 위치로 정보의 우선순위를 만들 수 있다.<br>
위계가 무너진 화면을 개선 전/후로 비교할 수 있다.

- 시선의 흐름 패턴
    1. F 패턴: 글이 많은 화면 → 중요한 말은 줄 앞에
    2. Z 패턴: 요소가 적은 화면 → 행동 버튼은 끝 지점(오른쪽 끝)

- 화면의 주인공: 한 화면에서 가장 먼저 봐야할 정보를 정하고, 나머지는 그 뒤로 보냄.
- 위계를 만드는 도구: 크기(클수록 먼저 봄), 대비(차이가 클수록 눈에 띔), 여백(가까우면 묶이고 멀면 나뉨), 위치(왼쪽 위를 먼저 봄)
- 여백의 역할: 정보를 묶고 나누는 도구. 덩어리 사이를 넓히면 순서가 보임.

- 개선 전/후: 점검 질문(화면을 다 만든 후 위계를 확인함)

    | 질문 | 확인 |
    |---|---|
    | 3초 안에 주요 정보를 파악 가능 | 화면을 3초간 보고 가린뒤 우선순위 말해보기 |
    | 흐리게 봐도 순서를 기억 | 눈을 가늘게 뜨거나, 흐리게(멀찍이)해서 보기 |
    | 강조 색의 쓰임 정도 | 1~2곳 이상은 줄이기 |
    | 같은 역할 = 같은 스타일 | 같은 역할에 동일한 텍스트, 컬러 스타일이 적용됐는지 확인하기 |

    → Figma 앱에서 PC로 만든 프로토타입 연동이 가능해 더 현실적으로 점검해볼 수 있음.

> ***시각적 계층은 크기, 굵기, 색을 함께 바꿔가며 만든다.***
