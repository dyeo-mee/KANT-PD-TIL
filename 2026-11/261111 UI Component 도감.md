> 헷갈리는 UI 컴포넌트 도감
1. 입력/선택
- 버튼 vs 링크: 실행은 버튼, 이동은 링크
    - 버튼 - 무언가를 “실행”할 때 사용(한 화면에 가장 강한 버튼은 하나만 존재)
    - 링크 - 다른 화면, 페이지로 “이동”하거나 덜 중요한 보조행동 일 때 사용<br>
    (글자가 작아도 프레임을 넓혀서 터치영역에 반영)
- 토글 vs 체크박스: 토글은 바로 반영, 체크박스는 적용해야 반영
    - 토글 - 알림받기 처럼 상태를 유지해야하는 상황
- 라디오 vs 체크박스: 라디오는 하나만 선택(결제수단 등), 체크박스는 다중 선택
    - 라디오는 기본값이 필수로 설정돼야함
- Placeholder vs Label: 플레이스 홀더는 입력하면 사라지고, 라벨은 계속 남아있음
    - 텍스트 필드 - Text Field, Textarea
- 드롭다운 vs 칩: 드롭다운은 숨겨진 선택창, 칩은 펼쳐진 선택
    - 드롭다운은 선택지가 많은 경우 사용(6개 이상)
    - 칩: 가볍게 고르거나 지울 때 사용(칩은 누를 수 있지만 배지는 누를 수 없게 만듦)
- 스테퍼 vs 슬라이더: 스테퍼는 정확한 숫자를 입력(인원), 슬라이더는 비율 %(금액)를 입력
    - 스테퍼 - 작은 범위의 숫자를 정확하게 입력할 때 사용<br>
    (단계 표시 1→2→3 도 스테퍼라고 부름 or 스텝 인디케이터)

2. 이동
- 앱 바 vs 탭 바: 앱 바는 지금 화면의 정보, 앱 전체 이동은 탭바
    - (app bar = top app bar = navigation bar)
    - (tab bar = global navigation bar(GNB) = bottom bar)
- 탭 vs 탭 바: 탭은 화면 안 묶음(홈 화면에서 카테고리별 이동 등). 탭은 화면이 아예 전환될 때.
- 탭 vs 세그먼트: 탭은 관련없는 다른 묶음들, 세그먼트는 같은 데이터를 묶어놓음.(홈 안의 쇼핑/갤러리)
    - 탭 안에 세그먼트가 들어간 경우가 많다.
    - 세그먼트: 같은 데이터의 기준을 다르게 보는 것. ex. 지도 앱의 지도/위성 전환
- 햄버거 vs 케밥: 앱 전체 메뉴는 햄버거 아이콘, 항목의 더보기 옵션은 케밥 아이콘
    - 햄버거: 중요하지 않은 메뉴, 잘 안쓰는 항목을 주로 넣음
    - 케밥: 수정, 삭제, 신고처럼 항목안에 위치한 자주 안 쓰는 행동을 숨길 때 사용.<br>
    (ios는 햄버거 메뉴를 지양함. 직관성이 떨어지므로 대신 아래에 해당 항목을 늘어뜨림)
- FAB(Floating action button) vs 아이콘 버튼
    - FAB: 화면에서 가장 중요한 행동을 보여줌(ex.당근 글 올리기)
    - 아이콘: 뜻이 널리 알려진 행동을 짧게 보여줄 때 사용<br>
    → 뜻이 애매한 아이콘은 글자를 붙인다. 아이콘이 24px 여도 터치영역은 최소 44px

3. 알림/피드백
- 토스트 vs 스낵바: 알림만 할 땐 토스트, 알림과 행동까지 보여줄 땐 스낵바(실수를 만회할 버튼)
- 배너 vs 토스트: 배너는 남아있는 알림(close btn), 토스트는 잠깐 쓰고 사라짐
- 모달 vs 바텀시트: 모달은 사용자의 행동을 멈추는 내용이 담김(중요도 높음), 내용을 선택하며 흐름이 이어지는 것은 바텀시트
    (modal = alert)
- 툴팁 vs 팝오버: 툴팁은 주로 hover하면 보이는 짧은 설명 ⊕, 팝오버는 세부 항목을 선택(ex.캘린더 날짜 선택)
- 툴팁 vs 코치마크: 처음 한 번만 안내하고 사라질 땐 코치마크
- 스피너 vs 스켈레톤: 언제 끝날지 모르는 로딩은 스피너(수 십초), 로딩되는 동안 구조나 모양을 미리 보여주는 건 스켈레톤
- 프로그레스 바 vs 스텝 표시
    - 프로그레스 바: 비율로 진행도를 알려줌(업로드, 많은 항목의 설문을 진행할 때)
    - 스텝 표시: 단계별 진행도를 알려줌(이전 단계로 돌아갈 수 있는지도 보여줌)
- 배지 vs 칩: 새 알림, 안 읽은 개수처럼 “확인할 내용”이 있는 경우 배지로 알려줌

4. 콘텐츠 표시
- 카드 vs 리스트
    - 카드: 이미지 중심, 하나하나 독립된 콘텐츠에서 사용(ex. 장소)
    - 리스트: 글자 중심, 많은 항목을 빠르게 훑어볼 때 사용(ex. 설정메뉴, 채팅 목록)
- 아바타 vs 썸네일
    - 아바타: 사람, 계정 정보
    - 썸네일: 콘텐츠 미리 보기, 비율이 중요(1:1, 4:3, 16:9)
- 배너 슬라이더 vs 캐러셀
    - 배너 슬라이더: 한 장씩 꽉차게(이벤트 영역처럼 자동으로 전환/영역 명칭 hero)<br>
    → 번호나 몇번째 순서인지 나타내 줘야함.
    - 캐러셀: 여러 장이 이어져 보임(ex. 카드 묶음)

5. 정리
- 어떤 걸 사용할지 헷갈릴 땐, 목적을 먼저 떠올려볼 것.
    - 누르면 결과가 바로 반영돼야 하는가? - 토글 vs 체크박스
    - 선택지가 너무 많아 복잡한가? - 드롭다운 vs 칩
    - 행동 알림을 주고 행동 취소도 반영돼야 하는가? - 토스트 vs 스낵바
    - 사용자의 확인이 필수적인 내용인가? - 모달

- 같은 이름, 다른 뜻

    | 이름 | 뜻 1 | 뜻 2 |
    |---|---|---|
    | 스테퍼 | 수량 조절 | 단계 표시 |
    | 슬라이더 | 값을 고르는 막대 | 배너 슬라이더 |
    | 배너 | 사라지지 않는 안내 띠 | 광고, 이벤트 이미지 |
    | Navigation bar | iOS: 화면 위 앱 바 | Material 3: 화면 아래 탭 바 |
    
    - 출처와 참고
    : Apple HIG(Human Interface Guidelines), Material Design 3
