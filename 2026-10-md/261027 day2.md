## 1. AI가 답을 만드는 방법
- ai 기본 개념 관계  
    사람의 인지, 판단, 생성 능력을 컴퓨터로 구현 (= 사람이 정한 규칙만으로 움직여도 AI라 칭함.)  

    <details>
    <summary>ai의 계층 관계</summary>
        : ai > 머신러닝 > 딥러닝 > 생성형 ai > LLM<br>
        - ML(머신러닝): 규칙을 사람이 정하지 않고 데이터를 통해 스스로 학습<br>
        - DL(딥러닝): 다층 신경망으로 데이터 속 복잡한 패턴을 학습(뉴런)<br>
        - 생성형 AI: 새로운 콘텐츠를 만듦. 이 중 텍스트 생성에 특화된 모델이 >LLM<
    </details><br>

- ai 역할에 따른 비교
    1. 생성 결과: 예측형 vs 생성형
    - 예측형: 데이터를 바탕으로 미래 결과, 위험, 수요를 예측 (숫자, 라벨)
    - 생성형: 프롬프트를 바탕으로 새로운 콘텐츠를 생성 (글, 이미지, 컨텐츠)  
    저작권 문제 등 약관을 확인하는 것이 중요

    2. 기능적 분류
    - 멀티모달: 글, 이미지, 소리, 영상 등 여러 형식을 이해하고 생성  
    **(학습데이터 ↔ 프롬프트 형식이 어떻든, 양방향으로 모두 이해가 가능한 모델을 지칭)**  
        <details>
        <summary>오답노트</summary>

        - 디자인 실무에서 멀티모달(Multimodal) AI를 활용한 사례로 가장 적절한 것은?

            a.텍스트 프롬프트를 입력하여 새로운 브랜드 로고 이미지를 생성한다.<br>
            b.완성된 ui 화면캡처 이미지를 ai에게 보여주고 uxui 개선점에 대한 피드백을 받는다.

            내가 고른 답: a  
            정답: b  
            텍스트를 입력해 이미지를 생성했으니 멀티모달에도 해당하는 사례라고 생각함.
            하지만 멀티모달은 다양한 형식의 프롬프트를 이해하고 결과물을 내는 모델에 해당하며, 답안 a보다 b가 더 적절한 예시에 가깝다. 
            답안 a처럼 텍스트 프롬프트를 이해하는건 LLM이나 이미지 생성모델에 특화된 사례이기 때문.

        </details>
    - 에이전트형: 목표를 주면 계획을 세우고, 도구를 써 여러 단계 작업을 이어 수행함.  
    (claude code-codex 클로드 코드 or 웹 리서치, 브라우저 검색 에이전트)

- LLM이 답을 만드는 방식  
    : 대규모 언어 모델 - 많은 글로 배운 패턴을 담은 계산 덩어리<br>
    기존에 학습한 데이터를 꺼내오는 방식이 아닌, 확률에 기반한 다음 토큰을 골라 이어쓴다.  

    - 다음 토큰* 예측  
        앞의 글을 보고, 다음에 올 조각을 확률로 골라 붙이는 것.<br>
        => 같은 질문에도 답이 달라지는 이유  
        <details>
        <summary>토큰이란?</summary>
            : AI가 글을 처리하는 가장 작은 조각<br>
            오늘, 밥, 을, 맛있게, 먹었다.<br>
            같은 내용이라도 언어에 따라 조각 수(토큰)의 차이가 발생.
        </details><br>

- LLM의 한계: 할루시네이션(환각현상)<br>
    → 없는 사실이나 존재하지 않는 논문, 통계 자료를 마치 사실인 것처럼 지어내어 답변하는 현상<br>
    (정답처럼 보이는 문장을 만들고 점수를 받음)<br>
    <details>
    <summary>점수</summary>
        ai 모델에게 보상이란 방금 한 행동이 얼마나 좋았는지 나타내는 숫자 신호<br>
        감정을 느끼지 않기 때문에 점수가 높아지는 방향으로 가중치를 조정하도록 학습됨.<br>
        보상이 높았던 행동은 더 자주, 낮았던 행동은 덜 하도록 업데이트 됨.
    </details><br>

- 학습 데이터 + 컨텍스트<br>
    AI가 아는 것은 미리 읽은 글(학습 데이터)와 지금 넣어준 글(컨텍스트)이다.<br>
    사용자가 학습데이터를 **변경 불가** 컨텍스트는 **변경 가능**

- 지식 컷오프 : 학습 데이터가 끝나는 시점. 그 이후 일은 기본적으로 모름.
    (학습 업데이트가 되지 않은 상태)<br>
    → 최신 가격, 규정, 인물 정보 등은 꼭 따로 확인해야 함.

- RAG: 검색 증강 생성 (필요한 자료를 직접 모델이 찾아와 프롬프트에 추가하는 방식)<br>
→ 최신 정보의 빈 곳을 메워줌.<br>
→ 근거 문서 안에서 답하도록 유도하면 환각현상을 억제할 수 있음.<br>
but,<br>
→ 검색 데이터가 업데이트되지 않으면, 낡은 문서를 자신있게 근거 삼아 오답을 냄.<br>
→ 개정 전과 후의 문서 내용이 섞여있으면 충돌하는 내용을 가져와 혼란스러운 답을 함.<br>
ex) 되는데, 안됩니다.  

> LLM의 답은 '사실'이 아닌 '가능성이 높은 문장'<br>
    따라서, 컨텍스트 반영을 잘 해야함. → 먹이를 잘 줘야한다

    - 지연, 로딩 : 진행상황 보여주기(과정) → ux관점

    - 실패 케이스 : 요청이 많거나 조건이 맞지 않으면 답을 내지 못 하기도 함.<br>
        → 왜 안된건지 원인을 설명, 다음에 할 일 알려주기

- 들쭉날쭉한 경계 (Jagged Technological Frontier)
    - 글로 많이 기록된 영역은 잘하고, 기록이 드물거나 암묵지에 가까운 영역은 약함<br>

    - 정답 기준이 모호한 과업은 개선이 더딤
    - 구조적 한계 : 확률적으로 그럴듯한 출력을 하기때문에 정확한 계산, 최신 사실, 긴 다단계 추론에서 오류가 누적되기 쉬움.

## 2. 프롬프트 구성요소와 컨텍스트
> 컨텍스트: 내 목적에 대한 **맥락** 알려주기

- 좋은 프롬프트란?<br>
    : 내 상황을 모르는 동료에게 보여줬는데 헷갈려한다? → AI도 헷갈려 함.

- 프롬프트 6가지 구성요소
    - 역할(role, persona) : ai가 어떤 관점에서 일할지 (일반적인 말투, 관점 X)
    - 맥락(context) : 서비스, 사용자, 상황 정보
    - 과업(task) : 정확히 해야 할 일
    - 형식(format) : 결과의 형태, 분량, 구조
    - 제약+이유(constraint, reason) : 꼭 지킬 것과 하지 말 것<br>
    → 단순히 “뭐 하지마.” 보다 이유를 함께 알려주면 사용자의 의도를 파악하고 유사한 상황에 대한 판단도 하게돼 더 완성도 있는 결과물을 얻을 수 있음.
    - 예시(examples) : 원하는 결과의 샘플 (톤과 형식을 전하는 가장 확실한 방법)<br>
    → 예시가 하나만 있으면 같은 형식의 결과만 되풀이하지만, 3개 이상이면 셋을 조합한 결과를 만들어 냄

- 프롬프트 개선과 기록<br>
    : v0 → v3 처럼 단계별로 컨텍스트를 개선하며 결과물을 확인하기<br>
    한번에 여러개를 바꾸면 무엇 때문에 좋아지는지 확인이 어려움. (단계별 확인)

    - [실습: 프롬프트 개선](https://app.notion.com/p/2-11192c061ee583c386d7814322bf950d?source=copy_link "notion")<br>
        | 문구 하나를 v0에서 v3까지 고치고, 단계마다 기록하기<br>
        -> 원하는 결과물을 얻기 위해 6가지 구성요소를 잘 활용해보고 차이점을 알게됐다!<br>
        -> 구성요소는 체크리스트처럼 활용해 결과물의 정확도를 높이자!

- 컨텍스트 엔지니어링<br>
    : ai가 일하는 동안 보는 정보 전체를 골라 넣고 관리하는 일<br>
    ⇒ 원하는 결과가 나올 가능성을 가장 높이는, 가장 작은 양의 중요한 정보를 찾는 일<br>

    - 프롬프트, 참고문서, 디자인 시스템, 이전 결정, 대화 기록, 검색 결과 등 AI가 다룰 데이터를 관리
